# swift-cidr 0.5.0

## Summary

`swift-cidr` 0.5.0 adds public value types for exact inclusive IP address ranges
and normalized exact address coverage. These APIs complement canonical CIDR
prefixes; they do not change the meaning or behavior of existing types.

## Highlights

- Adds `IPAddressRange<Family>`, with `IPv4AddressRange` and
  `IPv6AddressRange` aliases, for exact inclusive address intervals.
- Adds `IPAddressCoverage<Family>` for normalized exact unions with
  binary-search containment.
- Adds `AnyIPAddressRange` for runtime-family parsing and mixed-family boundary
  collections.
- Uses the strict, package-defined `lower...upper` range text form.
- Encodes and decodes `IPAddressRange` and `AnyIPAddressRange` as that canonical
  single-string form. `IPAddressCoverage` deliberately has no public wire shape.
- Coalesces duplicates, containment, overlap, and adjacency without covering a
  gap; mixed-family coalescing emits IPv4 ranges before IPv6 ranges.
- Delegates `summarizedNetworks()` to existing `IPNetwork.summarize(from:to:)`
  behavior. The returned networks preserve exact address coverage but need not
  reproduce the original input prefix lengths.

## Compatibility and Downstream Migration

This release is additive. It does not change any existing `swift-cidr` API, and
it does not raise the Swift tools version, supported platform minimums, or
dependency requirements.

`cidrmerge` 0.2 will move ownership of `IPAddressRange`,
`AnyIPAddressRange`, and `IPAddressCoverage` from `CIDRMergeCore` into `CIDR`.
Downstream source should migrate its import accordingly:

```swift
// Before: types were implemented by cidrmerge.
import CIDRMergeCore

// After: shared address-coverage currency comes from swift-cidr.
import CIDR
```

Any temporary source-compatibility aliases or re-exports needed by
`CIDRMergeCore` are a downstream `cidrmerge` concern. They are not additional
or deprecated spellings in `swift-cidr`.

The coordinated release order is `swift-cidr` 0.5.0, `cidrmerge` 0.2.0, then
`swift-cidr-admission` 0.2.0. This keeps the canonical range types available
before either downstream package migrates to them.

Range endpoints retain literal address bits rather than the prefix-length
context of programmatic `IPAddress` inputs. Converting a range back to networks
therefore preserves the exact covered addresses, not the identity or prefix
lengths of the original network list.

## Validation Before Tagging

- Run `./scripts/test.sh`.
- Run `./scripts/benchmarks.sh build` and `./scripts/benchmarks.sh check`.
- Run `./scripts/linux-test.sh` and `./scripts/linux-test.sh benchmark-build`.
- Confirm the `CIDR`, `CIDRPOSIX`, and `CIDRNIO` products build.
- Create the SSH-signed annotated `0.5.0` tag with message
  `swift-cidr 0.5.0` only after the feature branch has been reviewed and merged.
