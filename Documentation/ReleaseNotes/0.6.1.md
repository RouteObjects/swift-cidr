# swift-cidr 0.6.1

## Summary

`swift-cidr` 0.6.1 makes the in-tree `CIDRNIO` `SocketAddress` bridge consume
the fixed-size octet projection introduced in 0.6.0. Integer storage remains
canonical for address identity and CIDR math.

## CIDRNIO Octet Integration

- On Linux and Apple OS 26 or later, IPv4 and IPv6 socket conversions transfer
  address bytes through `IPv4Address.octets` and `IPv6Address.octets`.
- Inbound socket identities still receive `/32` or `/128` context because a
  `SocketAddress` does not carry a prefix length.
- Prefixed IPv4 hosts retain their host bits during outbound projection.
- IPv4 network and directed-broadcast validation is unchanged.
- IPv6 flow-info and scope-ID rejection is unchanged.
- Port conversion and the `ByteBuffer` integer network-byte-order path are
  unchanged.

The `InlineArray` is a transient, owned transfer value copied to or from the
POSIX socket field. It is not the literal storage of `SocketAddress`, a
zero-copy representation, or a borrowed `View`.

## Compatibility

This patch release adds no public symbols and changes no public signatures or
availability. The package retains its Swift 6.2 tools floor and its macOS 15
and iOS 18 deployment floors.

Because `InlineArray` is not back-deployed, existing socket conversions use a
private, behavior-equivalent integer network-byte-order implementation on
supported pre-26 Apple deployments. Consumers resolving the compatible 0.6.x
range therefore keep the same source, deployment, and runtime contracts.

The allocation-free evidence for the core octet projection remains valid. It
does not mean that constructing a complete SwiftNIO `SocketAddress` is
allocation-free; SwiftNIO owns that socket storage.

## Unchanged Boundaries

- No octet API is added to `IPNetwork` or `AnyIPAddress`.
- `CIDRPOSIX` is not rewritten in this release.
- `ByteBuffer` read/write and compressed-literal formatting remain on their
  existing implementations and availability.
- Address storage, equality, hashing, ordering, parsing, formatting, and Codable
  behavior are unchanged.

## Validation Before Tagging

- Run the complete test suite with Swift 6.2 and Swift 6.3 on Linux.
- Exercise the octet-backed socket path on macOS 26 and Linux.
- Exercise the compatibility fallback at runtime on macOS 15 with a Swift 6.2
  toolchain.
- Build `CIDRNIO` for the retained macOS 15 and iOS 18 deployment floors.
- Verify exact IPv4 and IPv6 socket-byte identity, prefix dropping, host-bit
  preservation, and the existing rejection contracts.
- Compare the four existing CIDRNIO socket benchmarks before and after the
  change. Allocation and ARC counts must remain stable; wall-clock values are
  observational rather than cross-machine claims.
- Compare the public API with the `0.6.0` tag and confirm no signature or
  availability changes.
- Extract the symbol graph and build DocC with warnings treated as errors.
