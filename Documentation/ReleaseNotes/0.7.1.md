# swift-cidr 0.7.1

## Summary

`swift-cidr` 0.7.1 corrects three IPv6 text-validation defects in the shared
parser. Malformed input that previously parsed successfully is now rejected;
valid addresses retain their existing values, formatting, and prefix context.

## IPv6 Literal Validation

The shared IPv6 parser now rejects:

- Hextets longer than four hexadecimal digits, including zero-padded values
  whose numeric value fits in 16 bits, such as `00000::1`.
- A terminal single colon, such as `1:2:3:4:5:6:7:8:` or `::1:`.
- A double colon that compresses no words, such as `1:2:3:4:5:6:7:8::`.
  An embedded IPv4 tail contributes two words to this validation.

These checks implement the address-text rules in
[RFC 4291 section 2.2](https://www.rfc-editor.org/rfc/rfc4291.html#section-2.2).
They apply through the existing shared parser to concrete and mixed-family
addresses and networks, CIDR-qualified text, range endpoints, JSON decoding,
and `CIDRArgumentParser` conversions, including bracketed IPv6 endpoints.

Valid compression at the beginning, middle, or end remains supported,
including compression of exactly one zero-valued word. IPv4-mapped IPv6
remains IPv6. The existing decimal leading-zero IPv4-octet acceptance is
unchanged, including in mixed IPv6 notation.

## Compatibility

This patch adds no public declarations or dependencies and changes no public
signatures, stored layout, or availability. The package retains its Swift 6.2
tools floor and its macOS 15 and iOS 18 deployment floors.

Integer-backed identity, CIDR math, canonical full-form parsing, formatting,
and valid-input Codable behavior are unchanged. Previously accepted malformed
IPv6 strings now produce `nil` from failable parsers, a decoding error through
Codable, or an invalid-value result at the argument-parsing boundary.

Consumers that require this validation correction should declare 0.7.1 as
their minimum version, rather than relying only on a local resolved-file pin.

## Validation Before Tagging

- Run the malformed-input regressions and the complete test suite.
- Validate Linux with Swift 6.2 and Swift 6.3, and build all four products at
  the retained Apple deployment floors.
- Compare the public API against 0.7.0 and confirm no declarations or
  availability changed.
- Compare the focused IPv6 parser benchmarks before and after on the same
  machine, including allocation and ARC metrics; check committed thresholds
  without recalibrating them.
- Run changed-code formatting checks and `git diff --check`.
- Review and integrate the signed correction before separately approving the
  signed patch tag and immutable Release. Leave 0.7.0 unchanged.
