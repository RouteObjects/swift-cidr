# swift-cidr 0.7.0

## Summary

`swift-cidr` 0.7.0 adds the opt-in `CIDRArgumentParser` product for parsing core
network currency values directly in Swift Argument Parser `@Option` and
`@Argument` properties. The surface includes the types needed by `bgpls`,
reusable family-bound composition values, and dual-stack boundary values for
other command-line tools: `Port`, `AutonomousSystemNumber`,
`IPAddress<Family>`, `IPEndpoint<Family>`, `IPNetwork<Family>`,
`PrefixLength<Family>`, `AnyIPAddress`, and `AnyIPNetwork`.

## CIDRArgumentParser

- Adds same-package `ExpressibleByArgument` conformances in a dedicated adapter
  target.
- Adds core `CustomStringConvertible` and `LosslessStringConvertible`
  conformances to `Port`, backed by `UInt16` parsing for the complete
  `0...65535` value space and canonical unpadded decimal output.
- Reuses `Port`'s lossless parser through Argument Parser's conditional witness,
  keeping standalone, endpoint, and CLI port text on the same parsing path.
- Reuses `AutonomousSystemNumber`'s strict `LosslessStringConvertible` parser:
  bare asplain decimal values are accepted; whitespace, signs, overflow,
  `AS`-prefixed text, and asdot text are rejected.
- Reuses the existing family-bound `IPAddress` literal parser. Bare IPv4 and
  IPv6 literals receive `/32` and `/128` context respectively; explicit valid
  prefixes and host bits are preserved.
- Adds `AnyIPAddress` for dual-stack CLI boundaries. It selects IPv4 or IPv6
  from the literal while retaining the same bare-address and explicit-prefix
  behavior as the family-bound parser.
- Reuses `IPEndpoint<Family>` parsing. IPv4 uses `address:port`, IPv6 requires
  `[address]:port`, the numeric port is mandatory, and bare address literals
  receive `/32` or `/128` context. Canonicalizable numeric port spellings use
  `Port`'s shared parser and render as unpadded decimal.
- Reuses `IPNetwork<Family>` parsing. CIDR notation is required and host bits
  are cleared to the canonical network boundary.
- Adds `AnyIPNetwork` for dual-stack network boundaries. CIDR notation remains
  required, the family is selected from the literal, and host bits are cleared
  to the canonical IPv4 or IPv6 network boundary.
- Reuses `PrefixLength<Family>` parsing and family validation. IPv4 accepts
  values in `0...32` and IPv6 accepts values in `0...128`; canonicalizable
  `Int` spellings retain the underlying parser's behavior and describe as
  unpadded decimal without a slash.
- Rejects DNS names without attempting name resolution. Family-bound address,
  endpoint, and network conformances also reject wrong-family literals.
- Leaves an omitted optional option as `nil`. An explicit empty value is a
  normal Argument Parser invalid-value error, not an instruction to synthesize
  `nil`.
- Supplies no finite `allValueStrings` enumeration for these large value
  domains.
- Adds adapter tests for IPv4 and IPv6 endpoint grammar, family-bound and
  mixed-family network canonicalization, family selection, positional
  arguments, family-specific prefix-length bounds, canonical help text,
  invalid-value propagation, and the absence of finite completion lists.

Consumers import all three modules explicitly; the adapter does not use
underscored re-exports:

```swift
import ArgumentParser
import CIDR
import CIDRArgumentParser
```

See [CIDRArgumentParser.md](../CIDRArgumentParser.md) for package-manifest and
typed-option examples.

## Packaging and Compatibility

- Adds Swift Argument Parser `>=1.7.0,<2.0.0` to the package dependency graph.
- Adds the `CIDRArgumentParser` library product and its test target.
- The `CIDR`, `CIDRPOSIX`, and `CIDRNIO` targets gain no target or link
  dependency on Argument Parser. Only the new adapter target depends on it.
- Because SwiftPM resolves dependencies declared by the package manifest,
  resolving `swift-cidr` also resolves `swift-argument-parser` at the overall
  package-graph level even when a consumer selects only `CIDR`.
- Existing `CIDR`, `CIDRPOSIX`, and `CIDRNIO` source APIs remain compatible; all
  public API changes from 0.6.1 are additive. Core `CIDR` gains `Port` string
  conformances, while every `ExpressibleByArgument` conformance remains
  isolated to `CIDRArgumentParser`.

This is a new minor version in a pre-1.0 package. Downstream packages constrained
to the 0.6.x line with `.upToNextMinor` do not adopt it automatically. To use
the adapter, update the dependency to `.upToNextMinor(from: "0.7.0")`, add
`CIDRArgumentParser` and `ArgumentParser` as direct target dependencies, and add
the explicit imports above.

## Deferred Surface

This release does not add `ExpressibleByArgument` to `AnyPrefixLength`,
`NetworkPrefixRange`, address ranges or coverage, `CIDRBlock`, or multicast
group/range types, including their mixed-family wrappers. DNS resolution,
service-name ports, ASN `AS` prefixes/asdot forms, and empty-string optional
coercion remain higher-layer or future concerns.

`Port(0)` remains valid shared currency. Rejecting zero for a remote peer port
is a `bgpls` policy decision rather than a `swift-cidr` parsing rule.

## Validation Before Tagging

- Run `./scripts/test.sh` and build the `CIDR`, `CIDRArgumentParser`,
  `CIDRPOSIX`, and `CIDRNIO` targets explicitly.
- Validate Swift 6.2 and Swift 6.3 on Linux.
- Build the applicable targets at the macOS 15 and iOS 18 deployment floors.
- Verify a temporary consumer pinned to Swift Argument Parser 1.7.0 exactly.
- Extract and audit the public symbol graphs, and build DocC with warnings
  treated as errors for all documented targets.
- Run the benchmark builds and configured threshold checks because the package
  and module boundary changed. If host-sensitive thresholds fail, compare with
  untouched 0.6.1 under equivalent idle conditions and require no attributable
  regression rather than updating thresholds from noisy measurements.
- Compare public API against 0.6.1 and confirm the changes are additive: core
  `CIDR` gains only the intended `Port` string conformances, and all
  `ExpressibleByArgument` additions are isolated to `CIDRArgumentParser`.
- Confirm `CIDR`, `CIDRPOSIX`, and `CIDRNIO` do not acquire an Argument Parser
  target or link dependency.
- Run formatting checks and `git diff --check`.
- Create the SSH-signed annotated `0.7.0` tag with message
  `swift-cidr 0.7.0` only after the feature branch has been reviewed and merged.
