# Reproduction and preserved evidence

Use a new experiment directory under `$HOME/Downloads` for every new candidate/run. Preserve the original directory and artifacts. The original experiment is `cidrmerge-inplace-coalescing-20261115T221013Z`.

## Frozen sources and dependency graph

`control/before.json` records both baseline commits and original repository files. `control/cidrmerge-main.tar` and `control/swift-cidr-main.tar` preserve the committed trees. `sources/B` contains baseline and `sources/C` candidate, each with sibling `swift-cidr` and `cidrmerge` packages. Apply the complete upstream patch only to C; the test file is included. Both experiment-only CLI manifests use `.package(path: "../swift-cidr")`. Preserve the identical seven other CLI pins and the upstream package's original five pins. `control/dependency-normalization.json` records the local substitution and lock normalization. Canonical manifests remain untouched.

`control/source-freeze.json` hashes every frozen snapshot file. Verify it before and after testing/timing. Build ordinary release binaries first, then copy them to `macos/bin/B` and `macos/bin/C` before any test builds. The ordinary binaries must remain unchanged.

## macOS

Use Xcode 27.2 / Apple Swift 6.4.2 as recorded by runtime/toolchain freezes. The original commands are preserved in build receipts. In a fresh directory with prepared sources and caches:

```sh
python3 control/build.py B cidrmerge build release
python3 control/build.py C cidrmerge build release
# For B and C, run each package (swift-cidr and cidrmerge) in debug and release:
python3 control/build.py B swift-cidr test debug
# Repeat the preceding test invocation for the other seven variant/package/configuration combinations.
python3 control/mac_prepare.py sources
python3 control/mac_prepare.py inputs
python3 control/mac_correctness.py
python3 control/mac_prepare.py benchmark
python3 macos/control/run_matched.py --validate-only

```

Native `/usr/bin/time` must be able to read resource information. The original sandboxed warmup failed; its data remains in `macos/measurements`. The valid matrix uses `run_matched_02.py` and `macos/measurements-02`; its only scheduling-script change is the fresh output directory, bound by `retry-02-freeze.json`.

Run scale separately, using the independent fixtures generated by `control/prepare_scale.py`:

```sh
python3 control/scale_bench.py --root macos --fixtures scale --output macos/scale-measurements
```

`control/mac_followup_02.py` selected every primary case with an individual elapsed/RSS increase above 5%. Smaller-input follow-ups use the same scale runner with `macos/scale-followup-inputs/reference.json`. Each follow-up has six pairs and one excluded warmup per configuration; it remains separate from the original run. Never retry into an existing directory.

## Linux

The shared frozen harness is under `shared`, with platform copies under each `control` directory. Platform configurations record toolchain paths, native architecture, build jobs, source/reference inventories and runtime identities. ARM64 uses cached native OrbStack images, not emulated x86-64. swift-dev uses the separately installed Swift 6.4.2 toolchain. `build_tests.py` freezes ordinary CLI binaries before running full upstream and CLI Debug/Release suites. `run_correctness.py`, codegen gate and runtime freezing precede `prepare_benchmark.py` and `run_matched.py`. `scale_bench.py` is the same source used on Mac, with Linux exact-child wait4 resources.

For swift-dev, post-sample wrappers share verified byte-identical stdout files through a task-owned immutable hardlink store. Each original timing function completes and writes its sample receipt before the wrapper compares bytes and changes storage. Every per-process output path remains readable. The store/protocol/helpers are frozen and audited; this adds between-sample I/O, which is disclosed as a measurement condition. The older cache cleanup proposal was not used.

The primary harness uses the original eight split-family corpora and three native mixed cases. Preserve 132 measured samples and 22 warmups/platform, complete outputs, raw resource records, binary/runtime hashes and all failed attempts. Keep at least 3 GiB free throughout measurement. No task-owned builds, tests, profiling or other Mac/OrbStack timing may overlap a timed run. The platform directories retain native launch/configuration commands; ports, cached image IDs and machine allocation are evidence-specific and must be reverified for a rerun.

## Profiling and retention

`control/profile_heap.py` preserves the fresh-main paused-process snapshots; it verifies inspection/ordinary executable-section equality and complete output after resuming. Delays are phase-search observations, not synchronization guarantees. `profiling-main.json` indexes all successes and the permission failure.

`retention/source/main.swift`, `retention/build_probe.py` and `retention/run_probe.py` in the original Downloads experiment preserve the external retention client. Run each B/C overlap, adjacent and disjoint case in a fresh process outside timed benchmarks. The checkpoint occurs after the input-building function returns and while the result is kept alive. Match the emitted element address to heap allocation and VM region. Inspection requires permission to inspect the owned process. Instrumented elapsed/peak values are not throughput measurements.

## Audits and public copies

Per-platform public manifests identify each original file by relative path, byte count and SHA-256, then bind its transformed public copy. Home paths are redacted; numeric measurements are unrounded. Native audits recompute all schedules, raw timing/RSS values, reference hashes and paired/group statistics. Raw stdout/stderr, executable files, fixtures, complete profiler captures and logs remain in Downloads. Preserve all historical report and threshold directories.
